## 2. 本案问题地图（现象 → 数据流）

### 2.1 现象三件套

| # | 现象 | 硬数据 |
|---|------|--------|
| S1 | **死循环吃内存** | RSS 每 0.5s +250MB（≈500MB/s）、CPU 100%；曾单次涨到 23293MB 被杀；`-E` 与 `build -backend asm` 双路径同炸 |
| S2 | **L009 伪位置** | 报 `invalid type suffix`，位置指向已验证无害的行（如 `let m: i32 = ix0 >> 20;` 的 col 4＝`let` 的 `e`）；该行在截断文件里词法全绿 |
| S3 | **行号 -10 漂移** | 哨兵 L009 种在 skel 行 30 → 报 20:19；种在行 40 → 报 30:19；种在 ≤25 行 → 行号正确。列号始终正确 |

### 2.2 数据流（谁产生、谁存储、谁消费）

```
源文件 u8[]
  → lexer.x 词法（Lexer struct = {pos: usize, line: i32, col: i32}，纯位置状态）
  → parser.x（.x 权威）各 parse_*_into
  → glue 层（*_glue / *_into_c）
  → C seed slices（compiler/seeds/parser_asm/parser_asm_expr_binop_slice.inc，经
    pthin_expr_binop.from_x.c 编入二进制；内含 TLS 单 token peek cache，commit b580f5487 09-03 引入）
  → AST arena（expr_alloc / get / set）
```

**观测到的死循环形态**（lldb + sample 双确认）：
- 栈**浅**（40 帧到底）——**不是递归爆栈，是 `for(;;)` 链循环不前进**；
- 热叶 `parser_asm_binop_wrap_c +304`，其上 `parser_asm_parse_compare_into_slice_c +340` → `parser_asm_binop_single_tok_chain_c +124` → … Pratt 全链（logor→…→term）→ `parser_parse_one_function_impl` → if_stmt → cond_expr；
- 每圈循环 `ast_arena_expr_alloc` + get/set 各一次 → **arena 线性增长**＝S1 的 500MB/s；
- 推论：循环体内 peek 永远看到同一运算符 token，或子解析返回的 `out->next_lex` 回指运算符位置——**词法游标被写回/缓存机制打回原地**。

### 2.3 关键悖论（根修前必须解释）

该触发形态（括号二元子表达式条件 + 后随赋值）在任何真实代码库里遍地都是，但本仓日编译、L2 5 产品、exp/log 全文件 `-E`（含大量相似形态）**全绿**。结合 §3.2 非单调前缀实验：**触发还叠加了按文件内容变化的 AST/arena 分配状态协同条件**——同一形态在 A 文件炸、B 文件过。所以它是**随机埋雷**：现有全绿不证明安全，任何一个新 commit 都可能让某个文件开始楔死。

### 3.2 关隘实验：保配平删块 + 前缀二分

- 六大功能块逐个删除（vA tiny-punning / vB subnormal 块 / vC vD 两个 bit 循环 / vE rounding / vF 尾部 punning）→ **全炸** → 触发点在共有骨架或多处同型存活；
- 骨架单独（skel.x，64 行）→ 炸；
- 前缀族：sf14 过、**sf21 炸、sf28 过**、sf40+ 炸 —— **非单调**，锁定「状态协同」（§2.3）。

### 3.3 哨兵插桩技术（本案最有用的黑盒工具）

利用 L009 sticky「首次 occurrence 定位置、报一次」语义，在指定行种真 L009（`  let _s: i32 = 42zz;`）：

- 哨兵先于伪触发 → 以哨兵位置报告 + **fake-EOF 干净中止解析**（运行完成）；哨兵晚于伪触发起点 → 楔死（哨兵永远没被扫到）；
- 由此夹出：**楔死起点 = skel 行 40 `m = (m - (m & 1)) / 2;` 的解析**（哨兵种行 40 前→完成；种行 41+ → 楔死；种行 5（块注释内）→ 楔死，注释内不计数，符合预期）；
- 同时暴露 S3 行号 -10 漂移（哨兵行 30→报 20、行 40→报 30；≤25 全对）——**词法 line 计数在行 25→30 区间被弄丢 10**，而 col 恒正确，说明漂移发生在 line/col 维护或写回层，不是字节 pos。

### 3.4 最小复现与触发边界（g/e/f/c/d 系列，9-10 行文件）

**最小复现 g5（100% 楔死，build 与 -E 双路径）**：

| 变体 | 条件 | if 后语句 | 结果 |
|------|------|-----------|------|
| e1 | `m == 1` | `m = m / 2;` | ✅ 过 |

| g3 | `(m & 1) == 1` | `return m / 2;` | ✅ 过 |
| **g5** | **`(m + 1) == 1`** | **`m = m / 2;`** | ❌ **炸** |
| **f1/f3** | **`(m & 1) == 1`** | **`m = m / 2;` / `(m - 1) / 2`** | ❌ **炸** |

**边界结论**：必要条件 ＝ ① 条件形如 `(expr ⊕ expr) == expr`（括号内是二元运算，⊕∈{+,&,…}）；② if 块**后随赋值语句**（return 不触发）。`/`、`*`、`(m - 1) / 2` 均可当触发后随句。

## 4. 根因假设（按证据排序，下一步从 H1 查）

- **H1（首要）：binop slice 的 peek/advance 写回链有洞。**
  `parser_asm_expr_binop_slice.inc` 的链循环（peek→匹配→`advance_from_peek`→子解析→wrap）纸面正确、cache 键 (data,len,pos,line,col) 对 `{pos,line,col}` 结构完备；但 ① `parser_asm_lex_from_result_val_into` 的实际写回未读；② `parser_asm_parse_if_stmt_into_slice_c +360` / `parser_asm_parse_cond_expr_into_slice_c +284`（lldb 栈上 spinning 的上层）的 `next_lex` 写回未读；③ `.x` 权威 parser.x 的 if/cond 路径与 C seed 是否同语义未对照（G.7 双权威漂移嫌疑）。**子解析对「不认识的 token 返回 ok 但 next_lex 不前进」任何一处疏漏都会精确复现本死循环。**
- **H2：结构布局/调用约定漂移。** seed 侧 `struct parser_asm_lexer{pos,line,col}` 与 .x 侧 Lexer 必须逐字段一致；9.6.3（09-07）刚动过 parser.x。布局错位会自发产生位置错乱、伪 L009（游标落进 `ix0u` 这类「字母+数字+字母」标识符的数字上 → 数字后跟 alpha → 真 L009 但位置乱）、行号漂移三件套。
- **H3：line/col 计数器在 peek-restore 时丢失**（S3 的 -10 直接来源；可与 H1 同根：restore 恢复 pos 但 line/col 取自别处）。
- **H4（次要）：sticky L009 全局与 peek cache 交互。** cb.x 无任何输出即爆炸 → 楔死不依赖 L009；L009 是伴生症状非必要条件。

## 7. 结案（根修）

**产生点**：`parser_asm_scan_sync_after_if_stmt_c`（`compiler/seeds/parser_asm/parser_asm_if_stmt_slice.inc`）。消费：`parse_if_stmt` 的 `lex_out` → 外层 block/onefunc 语句循环。

**H1 证伪**：binop peek-cache 单圈 `==` 正确前进（pos 53→56→58）；死循环是 **compare 被外层按同一 `if` 起点反复重入**（ENTER pos=46 周期 +3 行）。

**为何「后随赋值」才炸**：`realign_lex_after_if_arm` 若下一 token 是 `return` 则停；若是 IDENT 赋值则回扫 160 字节命中同一个 `if`。g3（return）绿、g5（`m = m / 2`）红。

**为何「括号二元」才炸**：扫句器把 `if (` 当整段 `(cond)`，只跳第一对括号；`(m + 1) == 1 {` 在 `==` 处找不到 `{` → 退回 `lex_at_if`。`if m == 1 {` / `if (m == 1) {` 能扫到 `{`。

**根修**：取消 paren-form 特判；`if` 关键字后一律按括号深度 0 找 then `{`（wave361/650 与 parse_cond 不再剥前导 `(` 对齐）。禁止在 sqrt 源改写法绕雷。

**验收（mac L2）**：g5/g2/g3/`(x >> 2) != 4`＋后随赋值 全 parse+typeck；g5/shift_ne `build -o` run rc=0；L2 5/5；WIP `runtime_math_libm.x -E` typeck OK。Ubuntu 金标随 9.2.4 子波收口再真冷。

**下一刀**：9.2.4 sqrt+cbrt seed 孪生（禁再绕 parser）。
